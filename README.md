# LeilMat

**AI-native alloy design platform** — phase equilibria, solidification, precipitation,
yield strength, cost, and inverse design across a unified API with conformal
uncertainty and source provenance on every number.

Live target: **leil.xyz** (planned).  Built for working metallurgists, materials
engineers, and product designers who want fast, scientifically defensible answers
to "what alloy should I use, and how confident are we?"

---

## Quick start

The fastest way to see LeilMat work end-to-end is the 6061-T6 demo script.  It
takes one composition through every sprint's module-level API in sequence and
prints a narrated trace — no FastAPI, no UI, no Docker.

```bash
git clone https://github.com/MoezGH/LeilMat.git
cd LeilMat

python3 -m venv .venv
source .venv/bin/activate
pip install -r apps/api/requirements.txt

# Trained models are not stored in git (pickles execute code when loaded).
# Train them once — a few minutes; downloads the matbench steels dataset.
python -m apps.api.ml.training

python scripts/demo_6061_t6.py
```

Expected output (8 steps, ~7 s on a 2024 Mac):

```
[1/8  CALPHAD equilibrium]   FCC_A1 0.991, AL13CR2 0.007, MG2SI 0.003 @ 803 K
[2/8  Scheil]                — skipped (slow); pass --include-slow
[3/8  TTT]                   — skipped (Fe-C only; not applicable to Al)
[4/8  Microstructure]        — skipped (slow); pass --include-slow
[5/8  KWN precipitation]     β″-Mg₂Si: vf 0.022, r̄ 12.3 nm  (lit. ~0.012, ~5 nm)
[6/8  Yield strength]        278 MPa  (lit. 276 MPa)  ·  CI [223, 333] MPa
[7/8  Hierarchical cost]     $16.72/kg  (commercial AMS quote ≈ $9.50/kg)
[8/8  Inverse design]        Aerospace Al wing skin brief (3 objectives, 2 constraints)
```

Optional flags: `--include-slow` to add Scheil + Taichi (~5-15 min total),
`--json` for a machine-readable summary.

### Running the full API + UI locally

```bash
# Backend (FastAPI on port 8000)
python -m apps.api.ml.training           # one-time: trains ALL yield-strength models
uvicorn apps.api.main:app --reload --port 8000

# Frontend (Next.js on port 4000) — separate terminal
cd apps/web && npm install && npm run dev
# → http://localhost:4000/canvas
```

OpenAPI docs at **http://localhost:8000/docs**.  See `.env.example` for the
optional OPENROUTER + Materials Project keys (used by the Global AI panel
and the live phase-diagram explorer respectively).

## Scientific basis

Every API response carries `{source, calibration, ci_low, ci_high, coverage}`
per property so the UI can render the right badge.  No silent black boxes.
The single-source-of-truth scorecard is generated by:

```bash
python -m apps.api.ml.eval.unified_scorecard --refresh all
# → docs/SCORECARD.md
```

It aggregates every sprint's runner into one Markdown document.  Slow runners
(Scheil, LOO, ablation) cache to JSON; nightly CI runs the slow set.

| Sprint | Source tag | Calibration approach |
|---|---|---|
| 1     | `calphad_pycalphad`        | Deterministic — pycalphad equilibrium against open TDBs |
| 2     | `scheil_pycalphad`, `ttt_kirkaldy_venugopalan` | Deterministic + empirical (TTT Q values from Kirkaldy 1984) |
| 2.6   | `taichi_kwc`               | Reproducibility against Kobayashi 1993 Fig. 4 dendrite morphology |
| 3+4+6 | `rf_<family>`              | Per-family Random Forest, KNN-OOD gate, split-conformal 90% intervals |
| 5     | `kwn_robson_2004`          | γ + diffusion calibrated against TEM/SAXS canonical set (Bourgeois, Marioara, Sha, Slama) |
| 7     | `botorch_qehvi`            | BoTorch qEHVI + hard-constraint feasibility filter |
| 8     | `cost_v2_hierarchical`     | Spot × form × cert × HT + supplier overhead; 17 canonical commercial quotes |

### Per-property accuracy (post-Sprint 6)

| Property      | Method                                                                | Accuracy (CV MAE) |
|---------------|-----------------------------------------------------------------------|-------------------|
| Density       | Rule of mixtures (1/ρ = Σ wᵢ/ρᵢ)                                       | 1–4 % vs experiment |
| Melting point | Magpie mean elemental T_m                                              | 5–10 % (overestimates for eutectics) |
| Yield strength | Per-family RF + temper one-hot + closed-form Labusch + Ardell Orowan + OOD gate + conformal interval | Al **42 MPa**, Ti 101 MPa, Ni 106 MPa, Steel 119 MPa |
| Elastic modulus | Voigt-Reuss-Hill on Ashby elemental moduli                            | ~10-15 % |
| Hardness, fatigue, corrosion | Tabor / σₑ-UTS / PREN family-rules                       | Qualitative |
| Formation E (optional)       | M3GNet (`matgl`), random supercell + N=6 replicas         | 80 meV/atom MAE on 18 phases; **skipped if `matgl` not installed** |

The headline number — **Aluminum CV MAE dropped from 80 MPa to 41 MPa (-49 %)** —
came from giving the model the temper as an input (Sprint 4).  See
[SCIENTIFIC_ROADMAP.md](SCIENTIFIC_ROADMAP.md) Sprint 4 for the before/after table.

## Limitations & honest caveats

- **Yield strength** uses per-family RFs with hard OOD refusal at the model
  boundary.  Compositions outside the family envelope get a clear refusal
  rather than a silent extrapolation.  Cross-validated MAE is roughly Al 42,
  Ti 88, Ni 110 and steel 119 MPa; the training sets are small (Ti 47 alloys,
  Ni 63) and Ni/steel are the weakest.  Composition and temper label alone cannot
  distinguish alloys that differ only in processing — among aged-Ni alloys with
  near-identical γ′ fraction, yield strength differs by ~185 MPa on average — so
  expect an error floor from that alone.
- **Reference data is partly unverified.**  The validation numbers are only as
  good as their reference values.  Auditing the 8 nickel external-validation
  values against manufacturer datasheets found **5 of 8 wrong** (now fixed); the
  Al/Ti sets, the holdout sets and the 25 calorimetry ΔHf references have not had
  that audit yet, so treat their headline numbers as provisional.  See
  `NOTICE.md` → "Data quality".  `docs/SCORECARD.md` is the source of truth;
  figures quoted elsewhere in this README can lag it.
- **CALPHAD** ships with 7 open TDBs whose terms differ per file (one is
  ODbL share-alike; one is labelled by its author "for testing only" — see
  `models/calphad_tdbs/README.md` and `NOTICE.md`).  Coverage is narrower than
  it looks: the bundled databases model **aluminium alloys, Ni-Al, Al-Zn, C-Fe and
  a few Ni-base ternaries/quaternaries**.  **Fe-Cr-Ni steels (304, 316) and
  multicomponent Ni superalloys (718) are refused** (`No CALPHAD database
  covers ...`) because no bundled open database models them; an earlier version
  answered stainless from an aluminium-alloy database and returned the wrong phase.
  Add a validated database (Thermo-Calc TCFE/TCNi, PanFe/PanNi, …) by dropping it
  into `models/calphad_tdbs/` and registering it.
- **KWN precipitation** treats interfacial energy γ and a vacancy-enhancement
  factor as per-precipitate calibrations against canonical TEM/SAXS data
  (the same pragmatic approach JMatPro uses).  Documented in the source.
  Multi-component γ' driving forces (IN 718 γ' = Al+Ti+Nb) are out of scope
  for the single-solute model; tracked as a Sprint 5.5 follow-up.
- **Microstructure**: Sprint 2.5's FiPy simulator is explicitly framed as
  "schematic" — anisotropic crystal growth but not Mullins-Sekerka.
  Sprint 2.6's Taichi simulator produces the textbook six-arm dendrite
  with side-branches but takes 3–10 minutes per run; not behind a sync HTTP
  endpoint yet.
- **Cost**: calibrated to commercial list prices; real contract prices vary
  ±20-30 % around list.  Test gate uses factor-of-2 to be robust to LME
  drift; daily updates to `elements_2025.py` would tighten it.
- **Global AI without RAG**: Sprint 9 (literature RAG with citation
  enforcement) is **deferred** until a redistributable authoritative corpus
  is available.  The chat panel currently produces ungrounded prose; it is
  marked as such in the UI.
- **Reference papers** are not redistributed with this repository (third-party copyright). `apps/api/rag/pipeline.py` will ingest any PDFs you place in `$LEILMAT_PAPERS_DIR`.
